# 2026-08-11 工作日志

## 修复 Hybrid 应用退出后 JS 中枢失效问题（主动发信 / 闹钟 / 桌宠）

### 根因
- 所有后台注入（心跳 BgPollReceiver、闹钟 InAppAlarmReceiver、桌宠双击）都通过 `AndroidMcp.mainActivity.findViewById(R.id.webview)` 找 Activity 的 WebView；用户退出应用 → Activity 与 WebView 销毁 → JS 引擎死亡，前台服务只保进程不保 JS。
- `MainActivity.onDestroy()` 主动调用 `stopBackgroundPolling()`，退出即取消心跳。
- `activeSessionId` 是纯内存变量，即使有第二个 JS 环境也无法恢复会话。

### 方案：Headless WebView 中枢（前台服务托管）
前台服务 `McpForegroundService` 内创建不挂窗口的隐藏 WebView 加载完整 `assets/index.html`，注册同一 `AndroidMCP` 桥接；所有 JS 注入目标改为 `AndroidMcp.getEffectiveWebView()`（中枢优先，Activity 兜底）。Activity 销毁后中枢由常驻保活通知保活。

### 改动文件
- `app/src/main/java/com/story/phone/AndroidMcp.kt`：单例化 `getInstance(context)`（applicationContext）；新增 `centerWebView` / `getEffectiveWebView()`；桌宠双击、下载进度回调改注入中枢。
- `app/src/main/java/com/story/phone/MainActivity.kt`：onCreate 用单例；**删除 onDestroy 里的 stopBackgroundPolling/unregisterMediaReceiver**；McpForegroundService 新增 `startHeadlessCenter()`（onPageFinished 注入 `initBackgroundCenter()`，onDestroy 销毁中枢）；BgPollReceiver / InAppAlarmReceiver 注入目标改 `getEffectiveWebView()`。
- `app/src/main/assets/app_chat.js`：`openWeChatDialog` 持久化 `mcp_active_session_id`；删除会话时移除。
- `app/src/main/assets/app_chat_mcp.js`：`_registerActiveAlarm` 持久化 `mcp_active_alarm_state`；`clearAlarmStatus`/`cancelActiveAlarm` 清除；文件末尾新增 `window.initBackgroundCenter()`（恢复会话与闹钟状态、标记 `__isBackgroundCenter`）。

### 防重
主动发信走 `db.desktop_pets` + localStorage 时间戳（`mcp_last_msg_time_{charId}`），双 WebView 共享 localStorage 天然防重。

### 验证
JS 三个文件通过 node --check。Kotlin 未本地编译（机器无 JDK/gradle wrapper），需用户在 Android Studio 构建。
真机验证要点：开启「设置-后台保活」开关（启动前台服务+常驻通知）→ 进会话 → 退出应用 → 观察：心跳日志、闹钟到点通知、桌宠冒泡/双击。
注意事项：厂商（小米/华为等）需允许自启动/后台运行白名单；强制停止应用会连前台服务一起杀，属系统限制。
