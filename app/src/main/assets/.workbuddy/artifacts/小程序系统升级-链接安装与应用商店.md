## 一、本次做了什么

把「叙事诗小手机」的小程序系统从「复制代码 / 导入文件」升级为**应用商店式分发 + 权限安全模型**：

| 能力 | 之前 | 现在 |
| :--- | :--- | :--- |
| 安装方式 | 上传文件 / 粘贴代码 | + **链接安装**（粘贴 `.js` 直链）<br>+ **应用商店导入**（store.json 一个链接装齐多个应用，一键更新） |
| 小程序能力 | 读写本地数据、调 LLM | + **调用 MCP 工具**（短信验证码、外部 API 等） |
| 密钥安全 | `api.getApiConfig()` 把明文 key 交给小程序 | 声明权限后**拿不到 key**；MCP 由宿主代理，服务器地址/鉴权头不进入小程序 |
| 权限控制 | 无（装了就全权） | **manifest.permissions 白名单**，未授权 API 直接裁剪；首次运行弹权限清单 |

## 三、使用方式

**链接安装**：工坊 →「安装小程序」→ 展开卡片 →「链接安装」输入框粘贴 `.js` 直链。

**应用商店**：工坊 →「应用商店」→ 粘贴 store.json 链接 → 导入全部应用；商店源保存后可随时「打开 / 更新全部 / 移除」。

**store.json 格式**（托管到任意 https 静态地址即可）：

```json
{
  "type": "miniprogram-store",
  "name": "商店名",
  "iconSvg": "<svg ...>",
  "apps": [
    {
      "id": "mp_store_sms_helper",
      "name": "验证码助手",
      "description": "通过 MCP 短信网关收发验证码",
      "version": "1.0.0",
      "author": "作者",
      "type": "tool",
      "iconSvg": "<svg ...>",
      "url": "https://host/apps/sms_helper.js",
      "permissions": ["mcp", "storage", "llm"]
    }
  ]
}
```

## 四、安全模型要点

1. **密钥留在宿主**：声明权限的小程序 `getApiConfig()` 只返回 `{url, model, temperature, hasKey}`；未声明权限的旧版小程序保持返回 key（向后兼容）。
2. **MCP 宿主代理**：`api.mcp.listServers()` 不含 url/headers；`api.mcp.invoke()` 走 `mcpClientSystem.callMcpTool`（含握手鉴权）。
3. **权限裁剪**：白名单外 api 方法被直接删除。
4. **首次运行确认**：仿应用商店权限弹窗，确认一次后记录。
5. 诚实提示：安装任意第三方小程序等于信任其作者（宿主为软隔离）；真正需要硬隔离可后续演进 iframe/Worker 沙箱（会牺牲现有同步 API 兼容性）。

## v2（同日）：精简工坊 UI + 链接规格与部署教程

用户反馈：既然「链接安装」输入框本身就能识别 store.json，独立的「应用商店」板块是冗余 UI。

- **删除**工坊「应用商店」独立 section 及全部 UI 函数（onAddStore/renderStores/openStore/showStoreModal/hashStr）与 `.mp-ws-store-*` 样式。
- **统一入口**：「链接安装」输入框自动识别 `.js` 直链 或 store.json 商店清单；粘贴商店清单即批量安装，重复粘贴即更新。
- **promote 增强**（WORKSHOP_PROMPT + README）：
  - 明确「可接受的链接」：`.js` 直链（GitHub raw / jsDelivr / Gitee 等）或 store.json 清单；需 https、免登录、匿名 GET 返回文件原文；浏览器受 CORS 限制（推荐自带 CORS 的托管，或 Android 真机原生桥绕过）。
  - 明确「不可用链接」：GitHub blob 网页、需登录的网盘页、HTML 包装页、需鉴权私有链接。
  - 要求 AI 输出「部署与导入教程」：至少两种部署路径（GitHub Raw / jsDelivr 示例）+ 工坊导入步骤。
- 宿主 API 能力保留（installStore/installStoreApp/updateStoreApps/商店源持久化），仅不再有独立 UI。

## 六、后续建议

- 若担心恶意小程序直读 `localStorage`（软隔离局限），可后续为「不可信来源」提供 iframe `sandbox` 严格模式。
- 商店清单可加 `sha256` 字段做代码完整性校验。
