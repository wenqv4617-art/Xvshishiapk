## 小程序系统升级：链接安装 / 应用商店 / MCP 安全桥

需求：安装小程序不再靠复制代码/导入文件，改为链接一键导入（应用商店式）；小程序要能调用 MCP 等全能能力，但用户密钥不暴露。promote（README/工坊 Prompt/开发日志）同步更新。

### 核心设计
- **统一链接安装 `installFromUrl(url)`**：拉取内容自动识别「单文件 .js」或「应用商店 store.json 清单」；复用 AndroidMCP 原生 HTTP 桥 + fetch 回退（`fetchUrlText`）。
- **应用商店**：`store.json`（type=miniprogram-store + apps[]，url 可相对、permissions 覆盖代码 manifest）→ `installStore` 批量导入；商店源持久化 `miniprogram_store_sources`；`updateStoreApps` 按 appId 锁定一键更新；`installStoreApp` 单应用安装。
- **权限声明式安全模型**：`manifest.permissions` 白名单（PERM_META 12 类 + `*`）；`applyPermFilter` 按白名单删除未授权 api 方法；未声明权限的旧版小程序全权限（向后兼容）；`ensurePermApproved` 首次运行弹权限清单（localStorage 标记一次）。
- **密钥不暴露**：声明权限后 `getApiConfig()` 只返回 `{url, model, temperature, hasKey}`；`api.mcp.listServers/listTools/invoke` 由宿主 `mcpClientSystem.callMcpTool` 代理，服务器 url/headers 不进入小程序作用域。
- **注册表字段**：permissions、manifestUrl、githubUrl（链接安装归 source=github，可更新可删除）。

## 赴约模式记录拼入线上上下文（新功能）

需求：在单聊/群聊对话详情加开关，开启后赴约模式（线下）未总结的对话记录按时间线拼入线上上下文，参与自动总结轮数统计与向量搜索原文；被线上总结后自动存档。

### 改动文件
- **index.html**：单聊详情面板 `details-merge-offline-toggle`、群聊详情面板 `group-details-merge-offline-toggle` 开关。
- **app_chat.js**：
  - 单聊详情加载/保存 `mergeOfflineIntoContext`（sessions 表新字段，未加 db.js schema 避免数据库迁移）。
  - `btnReply.onclick`（单聊+群聊共用）中：查询未存档赴约记录（`isTheater===0 && mergedArchived!==1`）与线上 history 按时间线合并；线下记录剥离 CoT/STATUS/TRANSLATE/MSG_ID/QUOTE 标签，加 `【线下赴约·名字】` 前缀 + 场景切换 system 提示（隔离线上线下格式）；`pushMergedMessage` 守卫 API 轮替约束。
  - `endAppointment` 只总结/删除未存档记录（`mergedArchived!==1`），已随线上总结的记录保留为历史回顾。
- **app_chat_group.js**：群聊详情加载/保存同一字段。
- **app_summary_memory.js**：
  - 新增 `getOfflineRoundsWithIds`（赴约轮次+消息id映射）与 `getMergedRoundsForSummary`（线上轮次保持索引、线下轮次追加在后）。
  - `checkAndTriggerAutoSummary` / `generateSummaryForRounds` / `loadSummarySettings` 改用合并轮次；`generateSummaryForRounds` 总结成功后把 [startRound,endRound] 内线下轮次标记 `mergedArchived=1`（自动存档）。
  - 新增 `embedOfflineAppointmentRounds`：未存档赴约轮次嵌入 dialogue_vectors，roundIndex 用负数隔离、offlineContentKey 幂等去重、isOfflineRound=1 标注；`rebuildDialogueVectors` 一键补建也覆盖。
- **app_prompts.js**：-590 原始对话检索输出标注"· 线下赴约"；检索查询文本（-600 上下文）合并未存档线下原文。

### 关键设计决策
- 线下轮次在总结统计中"追加"而非穿插，保证线上轮次索引与 summaries.endRound 语义一致（避免漏总结）。
- 存档采用 `mergedArchived` 标记而非删除，回顾舱（renderOfflineMessages）仍可见。
- 向量 roundIndex 用负数（-1,-2,...）与线上 0..N-1 隔离，升序后线下天然作为历史参与检索。

## v2 更新（同日）：总结改为严格时间线（消息级进度标记）

用户反馈：要求线上/线下**任意来回切换**时上下文与总结都按真实时间线组织、记忆互通。v1 的"线下轮次追加在后"在穿插场景会索引漂移、漏总结。

### v2 核心改造（app_summary_memory.js）
- **进度追踪从轮次索引改为消息级标记**：线上消息 `messages.summarized=1`，线下记录 `offline_messages.mergedArchived=1`。进度判定与列表位置无关 → 任意穿插安全。
- 新增纯函数 `buildRoundsFromStream`（统一时间线轮次算法，含通话记录/系统灰字处理，轮次带 ids/srcs/_isOffline/_doneAll）。
- `getTimelineStream`（线上未总结 + 线下未存档，按时间戳排序）/ `getPendingSummaryRounds` / `getFullTimelineStats`（面板统计）。
- `generateSummaryForRounds`：严格时间线 + 总结后按 srcs 标记 summarized / mergedArchived。
- `checkAndTriggerAutoSummary`：基于待总结轮次触发，单次上限 100 轮防 token 爆炸。
- `loadSummarySettings`：统计与手动总结默认区间 [1, pending] 同步。
- 修复：自动总结块多了一层 if 少一个闭合括号的语法错误。

### 验证
- 4 个 JS `node --check` 通过；时间线逻辑单测 9/9（穿插模式、轮次分组、进度标记、_doneAll 统计）。
- 测试脚本：.workbuddy/artifacts/test_timeline.js（保留可复跑）。

### 兼容性说明
- 老会话线上消息无 summarized 标记 → 首次自动总结会重新总结历史（一次性成本）。
- summaries.startRound/endRound 语义变为"总结时的待总结列表区间"，仅用于排序展示与检索去重（去重不精确仅影响 token 冗余）。
